# Datasets

All sources were verified on 2026-11-24. Caches live under `data/` and are
gitignored; committed artifacts are the 10 sample STEP files, model weights and
the 60-entry demo similarity library.

## 1. BRepLens Synthetic (primary)

| Field | Value |
| --- | --- |
| Generator | `src/breplens/geometry/synthetic.py` (CadQuery 2.8.0, dev-only) |
| Parts | 1,650 (150 per family, 11 families) |
| Splits | 1,156 train / 248 val / 246 test (stratified, MD5 assignment) |
| Size on disk | see `data/synthetic/manifest.json`; graphs + STEP + truth JSON |
| Generation wall time | recorded in `data/synthetic/manifest.json` (16 workers) |
| Labels | construction-derived per-face class + feature instance parameters |
| Units | mm |
| License | generated by this project → MIT |
| Reproduction | `python scripts/generate_synthetic.py --per-family 150 --workers 16` |

Families: plate_holes, plate_blind, counterbore, countersink, pocket, slot,
stepped_block, boss_plate, fillet_block, chamfer_block, bracket_mixed.
Classes (11): base, through_hole, blind_hole, counterbore, countersink, pocket,
slot, step, boss, fillet, chamfer.

Label derivation: expected construction geometry (axis lines, radii, planes,
cones) is matched to the exported B-Rep; pocket/slot/step wall faces are then
grown through concave edges from the known floor. Labels never come from the
recognizer. **Caveat:** the wall-growth step uses the same convexity signal that
the rule recognizer uses, so synthetic labels are not fully independent of the
rule feature geometry; the parameters and instance count are construction-derived.
Ground truth also shares the generator's idealizations. This is the documented
fallback dataset; it is not a substitute for MFCAD++.

## 1b. Multi-view render cache (optional Phase 9)

`scripts/render_dataset.py` renders six orthographic shaded views (±X/±Y/±Z) at
96×96 for the synthetic parts using a Pillow software rasterizer (no display).
The cache is gitignored; render wall time and counts are in
`data/renders/manifest.json`. The CNN/graph comparison is in
`results/cnn_eval.json`.

## 2. MFCAD (external benchmark)

| Field | Value |
| --- | --- |
| Source | https://github.com/hducg/MFCAD (verified, public) |
| Total models | 15,488 STEP + 15,488 `.face_truth` |
| Repository size | ~1.4 GB (shallow clone) |
| Labels | per-face integer ids from STEP face names + `.face_truth` pickle |
| Classes | 16: 15 machining features + stock |
| License | MIT (GitHub API license metadata; repository LICENSE file) |
| Subset converted | 3,000 evenly spaced over sorted filenames |
| Splits (ours) | 2,100 train / 452 val / 448 test (MD5, 70/15/15) |
| Conversion | 16 workers, 0 failures; exact wall time in `data/mfcad/manifest.json` |
| Reproduction | `python scripts/convert_mfcad.py --limit 3000 --workers 16` |

MFCAD has no holes or fillets in its label set and is known to be comparatively
easy for face classification (UV-Net reports ~99.95% face accuracy on it). It is
used as an **external sanity benchmark**, not as evidence of general machining
feature recognition. Our rule/GNN comparison collapses the 16 fine classes to 8
macro classes so the rule vocabulary is comparable.

## Data card (synthetic + MFCAD)

- **Intended use**: machining feature recognition research, retrieval evaluation,
  demo. Not for safety-critical manufacturing decisions or production CAM.
- **Personal data**: none.
- **Units**: millimetres after STEP import; no unit inference beyond OCP's
  `xstep.cascade.unit=MM` setting.
- **Known biases**: synthetic parts are axis-aligned, single-solid, sharp-cornered
  idealizations with a small family set; MFCAD contains only slots, steps,
  pockets, passages and chamfers and is CAD-generated/simple.
- **Redistribution**: sample STEPs are generated by this project (MIT); MFCAD is
  MIT but is not redistributed (downloaded by script); MFCAD++ is CC BY but was
  not downloaded.
